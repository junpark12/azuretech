Azure Tech Field Notes

This repository is a static English/Korean technical-documentation site.
There is no backend, tracking, remote font, runtime source-repository fetch,
or authentication requirement for visitors.

Layout
  content\*.json         Topic metadata and translated article HTML
  content\*.html         Article fragments referenced by bodyFile
  content\ko\           Korean translations of reviewed English articles
  locales\ui.json       English and Korean site-interface strings
  locales\ko-visuals.json Korean diagram and chart titles/captions
  locales\ko-portal-screenshots.json Korean screenshot descriptions/captions
  localization.ps1      Translation loading, source fingerprints, parity guards
  downloads\<topic>\     Reviewed, parameterized companion files
  assets\               Shared CSS and browser JavaScript
  docs\                 English site and shared assets; do not edit directly
  docs\ko\              Generated Korean index and topic pages
  build.ps1             Dependency-free Windows PowerShell site generator
  validate.ps1          Local artifact and link validation
  preview.ps1           Loopback-only preview server
  visuals.json          English conceptual diagrams and measured chart data
  visuals.ps1           Build-time inline SVG renderer (no remote images)
  portal-screenshots.json Reviewed screenshot placement, captions and SHA256
  portal-screenshots.ps1 Build-time screenshot renderer and image allowlist
  assets\portal\        Cropped, permanently redacted English portal captures

Build
  powershell.exe -NoProfile -File .\build.ps1
  powershell.exe -NoProfile -File .\validate.ps1

Use a shell allowed by your organization's execution policy. Do not change
machine or user policy merely to run these files. The build requires all seventeen
declared topics; -AllowPartial is for local work in progress only.

Preview
  powershell.exe -NoProfile -File .\preview.ps1 -Port 8765
  English: http://localhost:8765/azuretech/
  Korean:  http://localhost:8765/azuretech/ko/
  The /azuretech/ prefix deliberately matches the project-site path.

Bilingual routing
  Existing English URLs remain unchanged. Korean pages use /ko/ and retain
  the same topic filenames and section IDs. The language selector maps to
  the same article, preserves the last reading section (including ordinary
  scrolling without a URL fragment) and theme, and works as
  ordinary links without JavaScript (section retention requires JavaScript).
  The header stays visible while reading so switching language does not
  require scrolling back to the top; the desktop TOC sits below the header.
  Locale-local links keep navigation within the selected edition.
  No automatic language redirect, browser-language guessing, cookies or
  storage are required. Each language has canonical and hreflang metadata.
  Downloads, source code examples, diagrams' internal English labels, and
  actual English Portal screenshots are shared rather than copied into /ko/.

Translation maintenance
  English content is the reviewed canonical source, not the unredacted
  private Korean notebooks. Translate full prose, headings, narrative table
  cells, cautions, source descriptions, resource labels, and omission notes.
  Keep every pre/code block, inline code, HTML ID, URL, and numerical
  observation unchanged. Use the same download paths and metadata order.
  Korean JSON uses bodyFile for the translated HTML, sourceJsonSha256 for
  its English metadata file, and sourceBodySha256 for the English bodyFile
  (null when the English body is inline). Hash the original UTF-8 bytes.
  When English content changes, review and update the corresponding Korean
  translation FIRST, then refresh fingerprints with Get-FileHash -Algorithm
  SHA256. Never just update hashes to bypass a stale-translation failure.
  Caption translation files similarly fingerprint visuals.json and
  portal-screenshots.json. Preserve capture dates and measured chart data.
  UI translations use locales\ui.json's koSourceSha256: SHA256 of the UTF-8
  bytes of its English object serialized by Windows PowerShell with
  ConvertTo-Json -Depth 10 -Compress. Review Korean UI before refreshing it.
  build.ps1 and validate.ps1 reject missing/stale translations and mismatched
  code, sections, table structure, literal measurement cells, resource paths
  or metadata coverage. Narrative quantities may use Korean numeric units.
  Both languages must build together. There is no silent English fallback
  on a Korean page and no runtime third-party translation service.

Editing
  Edit the matching content JSON or bodyFile HTML fragment, rebuild, and
  review docs before committing. Translate sourceDocuments titles for Korean;
  never include private source URLs. downloads[].path is site-root-relative:
  downloads/<topic>/file.ext. Links written inside bodyHtml are relative to
  docs/topics/<topic>.html, so use ../downloads/<topic>/file.ext.
  Section headings must have unique IDs. The builder reserves "resources"
  and "editorial-notes" for the shared closing sections, and "visual-overview"
  for each topic's architecture figure.
  New articles set publishedOn (YYYY-MM-DD) identically in both languages.
  Dated articles appear first on the index; legacy articles retain their
  September 2026 article date even as the collection edition advances.

Visuals
  Topic cards reuse a decorative icon-only version of the article diagram.
  Article figures have localized captions and accessible text descriptions;
  diagram-internal labels remain English in both editions.
  On narrow screens, diagrams scroll rather than shrinking text to illegibility.
  Dashed paths distinguish configuration/secondary relationships; captions
  explain conceptual simplifications and unimplemented designs.
  Measurement charts start at zero and preserve source units. Translation
  values are eight-scenario means; ASE scale-out values are individual runs.
  Hosted Agent latency values are five individual request-to-stream-end
  observations, not first-text latencies or a representative distribution.
  Its chart sourceRow maps each bar to the corresponding measurement row.
  Do not add invented before/after numbers for topics without measurements.
  Original source screenshots are not used.

Portal screenshots
  A screenshot may specify capturedOn individually; otherwise the collection
  date is used. CVM form captures dated 2026-09-17 show unsubmitted controls,
  not a successful deployment, quota reservation, or hardware attestation.
  Captures dated 2026-09-16 show an available environment, not the original
  experiments. Captions state differences (for example, Node Subnet versus
  Overlay, nonmatching circuit-breaker settings, or absent image referrers).
  No resource creation or configuration changes were made for screenshots.
  Account headers and resource URLs are excluded. Identifiers are blacked out
  in the PNG pixels, not hidden by page CSS. Image metadata is not retained.
  Always inspect every image visually after masking; element positions can
  differ from their DOM child index. Update the reviewed SHA256 only after
  checking the resulting pixels. The builder refuses unreviewed PNGs.
  Keep source screenshots containing identifiers out of this repository.
  New screenshots must be approved for public release before committing.

Public-content safeguards
  Never copy source repositories wholesale into this public repository.
  Keep subscription/tenant/client/principal IDs, actual resource names,
  customer identities, internal hosts/IPs, user paths, keys, connection
  strings, and support records out of articles, downloads, filenames,
  metadata, comments, screenshots, commit messages, and history.
  Placeholders belong in public files. Populate them only in private local
  copies. Some templates are illustrative rather than directly runnable.
  No original screenshots or App Modernization assessments are included.
  Source-referenced files that were unavailable are explicitly not supplied.
  Historical tests are evidence from the original environment, not product
  guarantees or tests executed against the reader's Azure resources.
  Before publication, perform a manual content and resource review in
  addition to local automated checks. Automated patterns cannot establish
  that every possible sensitive value has been found.
